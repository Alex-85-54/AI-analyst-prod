# Таблица: also_viewed
**Синонимы:** также смотрели, совместные просмотры, сопутствующие товары, рекомендации на основе просмотров, cross-sell данные, поведенческий анализ
**Использование:** Таблица содержит данные о том, какие товары клиенты просматривали вместе (совместные просмотры). Используется для построения рекомендательных систем ("С этим товаром также смотрят"), анализа пользовательского поведения и выявления связанных товаров.
**Описание:** Таблица хранит агрегированную информацию о том, какие товары просматривались вместе в рамках одной сессии или с небольшим временным промежутком. Каждая запись — это набор товаров (items), которые просмотрел конкретный клиент за определенную дату. Данные имеют ограниченный срок жизни (TTL 7 дней).
- **shop_id**: Идентификатор магазина. Используется для разделения данных разных клиентов-магазинов. (`integer`, null: false)
- **client_id**: Идентификатор клиента (покупателя), совершившего просмотры. (`integer`, limit: 8, null: false)
- **items**: Массив идентификаторов товаров, которые были просмотрены вместе. Порядок элементов может иметь значение. (`string`, array: true, null: false)
- **date**: Дата, за которую зафиксированы данные о совместных просмотрах. Используется для партиционирования и TTL. (`date`, default: CAST(now(), 'Date'), null: false)
### Индексы и ключи
- **ORDER BY (`shop_id`, `client_id`)**: Ключ сортировки и первичный ключ в терминах ClickHouse. Оптимизирует хранение и выборки данных, где фильтрация идет по магазину и клиенту. Например, для получения истории просмотров конкретного клиента в магазине.
- **PARTITION BY (`toYYYYMM(date)`)**: Партиционирование по месяцам на основе даты. Ускоряет запросы, ограниченные конкретным месяцем, и упрощает управление устаревшими данными.
- **TTL (`date + toIntervalDay(7)`)**: Автоматическое удаление записей старше 7 дней. Гарантирует актуальность данных для рекомендаций и экономит место на диске.

# Таблица: bonus_histories
**Синонимы:** история бонусов, движения бонусного счета, лог бонусных операций, транзакции лояльности, бонусный журнал
**Использование:** Хранит детальную историю всех операций с бонусными баллами клиентов: начисление, списание, сгорание, отмена. Используется для анализа эффективности программ лояльности, расчета LTV, отслеживания использования бонусов и построения отчетности по бонусным счетам.
**Описание:** Таблица представляет собой лог всех изменений бонусного баланса клиентов. Позволяет проследить полный жизненный цикл бонусов: от начисления (rewarded) до использования (used), сгорания (burned) или отмены (cancelled). Каждая запись фиксирует изменение состояния бонусного счета по конкретной операции (заказ, активация и т.д.). Партиционирование по магазину обеспечивает быстрый доступ к данным в разрезе клиентов.
- **code**: Уникальный код операции или идентификатор транзакции (`integer`, limit: 8, null: false)
- **shop_id**: Идентификатор магазина, в котором происходит бонусная программа (`integer`, null: false)
- **client_id**: Идентификатор клиента (владельца бонусного счета) (`integer`, limit: 8, null: false)
- **status**: Статус операции (например, 'completed', 'pending') (`string`)
- **total_balance**: Общий баланс клиента после операции (`float`)
- **used**: Сумма использованных (списанных) бонусов в данной операции (`float`)
- **burned**: Сумма сгоревших бонусов (истек срок действия) (`float`)
- **cancelled**: Сумма отмененных бонусов (например, при возврате заказа) (`float`)
- **inactive**: Сумма неактивных бонусов (`float`)
- **rewarded**: Сумма начисленных бонусов (`float`)
- **purchase_date**: Дата покупки, к которой относится операция (`date`)
- **event**: Тип события, вызвавшего изменение баланса (например, 'order_paid', 'bonus_credited') (`string`)
- **order_id**: Идентификатор заказа, связанного с операцией (`string`)
- **bonus_status**: Статус бонусов в контексте операции (`string`)
- **amount_changed**: Сумма изменения баланса (положительная или отрицательная) (`string`)
- **activated_at**: Дата и время активации бонусов (`datetime`)
- **expiration**: Дата и время истечения срока действия бонусов (`datetime`)
- **activity**: Статус активности бонусов (`string`)
- **balance**: Текущий баланс клиента после операции (`float`)
- **date**: Дата операции (для партиционирования и отчетов) (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время создания записи в системе (`datetime`, default: now(), null: false)
### Индексы и ключи
- **ORDER BY (`client_id`)**: Ключ сортировки и первичный ключ в ClickHouse. Максимально оптимизирует выборки данных по конкретному клиенту (например, для показа истории операций в личном кабинете или расчета бонусной статистики).
- **PARTITION BY (`shop_id`)**: Партиционирование по магазину. Обеспечивает изоляцию данных разных магазинов и ускоряет запросы, работающие в рамках одного магазина (например, массовые расчеты или выгрузки для отчетности).

# Таблица: bonus_transaction_logs

**Описание:** Таблица на ClickHouse (MergeTree) фиксирует каждую транзакцию по бонусному счету с указанием источника (source_type/source_id). В отличие от bonus_histories, которая хранит состояния баланса, эта таблица сфокусирована на самих транзакциях и их контексте. Позволяет ответить на вопросы: "по какой причине были начислены/списаны бонусы", "какой заказ/событие вызвало операцию".
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **client_id**: Идентификатор клиента (`integer`, limit: 8, null: false)
- **order_id**: Идентификатор заказа, связанного с транзакцией (`string`, null: false)
- **event**: Тип события ('reward', 'use', 'burn', 'cancel' и т.д.) (`string`, null: false)
- **source_type**: Тип источника операции (например, 'Order', 'BonusPromotion', 'Manual') (`string`, null: false)
- **source_id**: ID записи в таблице-источнике (`integer`, null: false)
- **description**: Текстовое описание транзакции (`string`)
- **identifier**: Дополнительный идентификатор или код операции (`string`)
- **date**: Дата транзакции (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время создания записи (`datetime`, default: now(), null: false)
### Индексы и ключи
- **ORDER BY (`client_id`, `order_id`, `event`, `date`)**: Композитный ключ сортировки, оптимизирующий основные сценарии запросов:
  - `client_id`: быстрый поиск всех транзакций клиента
  - `order_id`: связь транзакций с конкретным заказом
  - `event`: фильтрация по типу события
  - `date`: хронологический порядок операций
- **PARTITION BY (`shop_id`)**: Партиционирование по магазину для изоляции данных и ускорения запросов в рамках одного магазина

# Таблица: bounces
**Синонимы:** отказы писем, баунсы, недоставленные письма, ошибки доставки email, проблемы с отправкой
**Использование:** Хранит информацию о недоставленных email-сообщениях (отказах/баунсах). Используется для мониторинга качества доставки писем, очистки невалидных адресов, анализа причин сбоев доставки и поддержания репутации отправителя.
**Описание:** Таблица на ClickHouse (MergeTree) логирует все случаи, когда отправленное письмо не было доставлено получателю. Фиксирует тип отказа (hard/soft bounce), причину и детальную диагностику от почтового сервера. Данные структурированы по источнику отправки (тип кампании и её ID), что позволяет анализировать качество доставки в разрезе различных рассылок.
- **shop_id**: Идентификатор магазина-отправителя (`integer`, null: false)
- **source_type**: Тип источника отправки (например, 'Mailing', 'Trigger', 'Transactional') (`string`, null: false)
- **source_id**: ID кампании/рассылки в таблице-источнике (`integer`, null: false)
- **client_id**: Идентификатор клиента-получателя (`integer`, limit: 8, null: false)
- **code**: Уникальный код события или идентификатор попытки отправки (`string`, null: false)
- **event**: Тип события (обычно 'bounce') (`string`, null: false)
- **bounce_reason**: Причина отказа (например, 'hard', 'soft', 'blocked') (`string`)
- **bounce_action**: Действие, предпринятое системой после отказа (`string`)
- **error_status**: Статус ошибки от почтового сервера (`string`)
- **diagnostic_code**: Диагностический код ошибки (подробное описание от сервера) (`string`)
- **email**: Email-адрес получателя, по которому произошел отказ (`string`)
- **date**: Дата события (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время создания записи (`datetime`, default: now(), null: false)
### Индексы и ключи
- **ORDER BY (`code`)**: Ключ сортировки по уникальному коду события. Оптимизирует поиск конкретного события и дедупликацию.
- **PARTITION BY (`shop_id`, `source_type`, `source_id`)**: Составное партиционирование, которое:
  - Изолирует данные разных магазинов
  - Группирует отказы по типу источника (рассылки/триггеры/транзакционные)
  - Позволяет быстро анализировать качество доставки конкретной кампании

# Таблица: bulk_click_maps
**Синонимы:** клики по картам ссылок, тепловая карта кликов, статистика переходов, интерактивная карта ссылок
**Использование:** Хранит данные о кликах по интерактивным картам (heatmaps) в массовых рассылках. Позволяет анализировать, на какие элементы и позиции в письме пользователи кликают чаще всего, оптимизировать дизайн и расположение ссылок.
**Описание:** Таблица на ClickHouse с движком CollapsingMergeTree, предназначенная для сбора и агрегации данных о кликах по различным позициям (ссылкам) в письмах. Каждая запись фиксирует клик конкретного клиента на определенной позиции (position) в рамках одной рассылки (bulk_campaign_id). Использует механизм "схлопывания" (collapsing) с полем sign для корректной обработки изменений и удалений данных.
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **bulk_campaign_id**: ID массовой рассылки (кампании) (`integer`, null: false)
- **client_id**: ID клиента, совершившего клик (`integer`, limit: 8, null: false)
- **code**: Код ссылки или идентификатор элемента, по которому кликнули (`string`, null: false)
- **position**: Позиция/индекс ссылки в письме (порядковый номер) (`integer`, null: false)
- **date**: Дата клика (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время события (`datetime`, default: now(), null: false)
- **sign**: Поле для CollapsingMergeTree (1 - добавление/обновление, -1 - удаление) (`integer`, limit: 1, default: CAST(1, 'Int8'), null: false)
### Индексы и ключи
- **ORDER BY (`client_id`, `code`, `position`)**: Ключ сортировки, оптимизирующий запросы:
  - `client_id`: поиск кликов конкретного клиента
  - `code`: анализ популярности конкретной ссылки
  - `position`: статистика по позициям в письме
- **PARTITION BY (`shop_id`, `bulk_campaign_id`)**: Партиционирование по магазину и кампании для:
  - Быстрого доступа к данным конкретной рассылки
  - Эффективного анализа в разрезе кампаний
  - Изоляции данных разных магазинов

Каждая запись соответствует одному событию для конкретного клиента в рамках кампании. Позволяет анализировать как общую статистику по кампаниям, так и детальные пути конкретных пользователей.
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **bulk_campaign_id**: ID массовой кампании/рассылки (`integer`, null: false)
- **client_id**: ID клиента-получателя (`integer`, limit: 8, null: false)
- **code**: Уникальный код события или идентификатор сообщения (`string`, null: false)
- **event**: Тип события (например: 'sent', 'delivered', 'opened', 'clicked', 'bounced', 'unsubscribed') (`string`, null: false)
- **channel**: Канал коммуникации ('email', 'web_push', 'mobile_push', 'sms', 'whatsapp') (`string`, null: false)
- **category**: Категория или подтип сообщения (`string`)
- **platform**: Платформа получателя (для push-уведомлений: 'ios', 'android', 'web') (`string`)
- **uid**: Уникальный идентификатор устройства или получателя (`string`)
- **message_data**: Данные сообщения (может содержать тему, текст, мета-информацию) (`string`)
- **stream**: Поток или группа рассылки (`string`)
- **location**: Геолокация или URL, где произошло событие (`string`)
- **date**: Дата события (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время создания записи (`datetime`, default: now(), null: false)
### Индексы и ключи
- **ORDER BY (`code`, `event`, `client_id`)**: Композитный ключ сортировки для оптимизации:
  - `code`: быстрый поиск по уникальному коду сообщения
  - `event`: фильтрация по типу события (например, только открытия)
  - `client_id`: агрегация по клиентам
- **PARTITION BY (`shop_id`, `bulk_campaign_id`)**: Партиционирование для:
  - Изоляции данных по магазинам
  - Быстрого доступа к статистике конкретной кампании
  - Эффективного удаления/архивации данных старых кампаний

# Таблица: cancelled_chain_runs
**Синонимы:** отмененные цепочки писем, прерванные автоматические серии, остановленные сценарии, логи отмен
**Использование:** Хранит информацию о случаях, когда выполнение автоматической цепочки писем (цепочки триггеров) было отменено для конкретного клиента. Используется для анализа причин прерывания коммуникаций, оптимизации сценариев, предотвращения нежелательных отправок и аудита работы автоматических маркетинговых кампаний.
**Описание:** Таблица на ClickHouse (MergeTree) логирует все ситуации, когда запланированная цепочка писем была отменена до своего завершения. Отмена может происходить по разным причинам: клиент отписался, совершил целевое действие раньше времени, попал в исключающий сегмент, или сработало бизнес-правило. Данные имеют ограниченный срок хранения (90 дней) для поддержания актуальности аналитики.
- **shop_id**: Идентификатор магазина, в котором работает цепочка (`string`, null: false)
- **chain_id**: Идентификатор отмененной цепочки писем (`string`, null: false)
- **client_id**: Идентификатор клиента, для которого отменена цепочка (`string`, null: false)
- **rule_id**: Идентификатор правила или условия, вызвавшего отмену (может быть пустым) (`string`)
- **reason**: Причина отмены (например: 'unsubscribed', 'converted', 'segment_changed', 'manually_stopped') (`string`, null: false)

Такой подход позволяет добавлять новые параметры событий без изменения схемы основной таблицы events.

- **value_string**: Строковое значение параметра (`string`)
- **value_date**: Дата как значение параметра (`date`)
- **date**: Дата события (для партиционирования) (`date`, null: false)

Позволяет отслеживать полную воронку взаимодействия: сколько пользователей начали просмотр, сколько досмотрели до конца, по каким слайдам кликают. Данные хранятся 2 года для долгосрочного анализа маркетинговых кампаний.
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **story_id**: ID истории (группы слайдов) (`integer`, null: false)
- **story_slide_id**: ID конкретного слайда внутри истории (`string`, null: false)
- **client_id**: ID клиента (если идентифицирован) (`integer`, limit: 8, null: false)
- **event**: Тип события:
  - 'show' — начало просмотра истории/слайда
  - 'click' — клик по слайду (по ссылке, кнопке)
  - 'swipe' — свайп для перехода к следующему слайду
  - 'close' — закрытие историй до окончания
  - 'complete' — полный просмотр всех слайдов
  - 'conversion' — целевое действие после просмотра (`string`, null: false)
- **sid**: Session ID — идентификатор сессии (`string`)
- **stream**: Поток или источник, в котором были показаны истории (`string`)
- **code**: Код, связанный с событием (например, промокод или идентификатор рекомендации) (`string`)
- **date**: Дата события (`date`, default: CAST(now(), 'Date'), null: false)
- **created_at**: Дата и время события (`datetime`, default: now(), null: false)
### Индексы и ключи
- **ORDER BY (`shop_id`, `story_id`, `story_slide_id`, `event`)**: Ключ сортировки, оптимизирующий:
  - `shop_id`: изоляцию данных по магазинам
  - `story_id`: анализ эффективности конкретной истории
  - `story_slide_id`: детальный анализ популярности отдельных слайдов
  - `event`: построение воронки событий (показы → клики)
- **PARTITION BY (`toYYYYMM(date)`)**: Партиционирование по месяцам для:
  - Анализа месячной динамики эффективности историй
  - Управления TTL
- **TTL (`date + toIntervalYear(2)`)**: Хранение данных в течение 2 лет

# Таблица: subscription_logs
**Синонимы:** логи подписок, история подписок и отписок, журнал изменения статуса подписки, аудит согласий
**Использование:** Хранит полную историю изменений статуса подписки клиентов на различные каналы коммуникаций (email, SMS, push). Используется для аудита согласий, анализа эффективности сбора контактов, отслеживания источников подписок, мониторинга уровня отписок и соблюдения требований законодательства о персональных данных (GDPR, 152-ФЗ).
**Описание:** Таблица на ClickHouse (MergeTree) логирует каждое изменение статуса подписки клиента. В отличие от client_unsubscribe_events, эта таблица хранит не только отписки, но и подписки, а также содержит полную информацию о контакте (contact_type, contact_value) и источнике события (campaign_type, channel, ip). Позволяет восстановить полную историю согласий для каждого клиента, что критически важно для compliance и юридической защиты. Данные хранятся 3 года (согласно требованиям законодательства).
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **client_id**: ID клиента (`integer`, limit: 8, null: false)
- **contact_type**: Тип контакта ('email', 'phone', 'push_token') (`string`, null: false)
- **contact_value**: Значение контакта (email, номер телефона, токен) (`string`, null: false)
- **campaign_type**: Тип кампании, вызвавшей событие ('bulk', 'trigger', 'popup', 'manual', 'import') (`string`, null: false)
- **event**: Тип события:
  - 'subscribe' — подписка на канал
  - 'unsubscribe' — отписка от канала
  - 'resubscribe' — повторная подписка
  - 'spam_complaint' — жалоба на спам
  - 'hard_bounce' — жесткий отказ (помечен как невалидный) (`string`, null: false)
- **channel**: Канал коммуникации ('email', 'sms', 'web_push', 'mobile_push', 'whatsapp') (`string`, null: false)
- **ip**: IP-адрес, с которого произошло событие (для юридической значимости) (`string`, null: false)
- **created_at**: Дата и время события (`datetime`, default: now(), null: false)
- **date**: Дата события (для партиционирования) (`date`, default: CAST(now(), 'Date'), null: false)
### Индексы и ключи
- **ORDER BY (`shop_id`, `event`, `client_id`)**: Ключ сортировки, оптимизирующий:
  - `shop_id`: изоляцию данных по магазинам
  - `event`: быстрый анализ подписок vs отписок
  - `client_id`: получение полной истории подписок конкретного клиента
- **PARTITION BY (`toYYYYMM(date)`)**: Партиционирование по месяцам для управления TTL
- **TTL (`date + toIntervalYear(3)`)**: Хранение данных в течение 3 лет (требование законодательства)

# Таблица: utm
**Синонимы:** UTM-метки, параметры трафика, источники переходов, маркировка визитов, атрибуция трафика
**Использование:** Хранит все UTM-параметры и другие маркеры источников трафика, с которыми пользователи приходят на сайт. Используется для сквозной атрибуции, анализа эффективности маркетинговых каналов, расчета ROI по рекламным кампаниям, сегментации аудитории по источникам и понимания, какие именно маркетинговые активности приводят наиболее ценных клиентов.
**Описание:** Таблица на ClickHouse (MergeTree) реализует гибкое хранение UTM-меток и других параметров перехода в формате "ключ-значение". Каждая запись соответствует одному UTM-параметру (utm_source, utm_medium, utm_campaign, utm_content, utm_term) или другому маркеру (gclid, yclid, fbclid, openstat) для конкретного устройства (did) в рамках сессии (sid). Такой подход позволяет легко добавлять новые типы меток без изменения схемы и эффективно анализировать, какие каналы приводят трафик. Данные хранятся 1 год для годовой маркетинговой аналитики.
- **did**: Device ID — уникальный идентификатор устройства (`string`, null: false)
- **sid**: Session ID — идентификатор сессии (позволяет группировать UTM-метки одного визита) (`string`, null: false)
- **shop_id**: Идентификатор магазина (`integer`, null: false)
- **param**: Название параметра:
  - 'utm_source' — источник кампании (google, yandex, facebook)
  - 'utm_medium' — тип трафика (cpc, organic, email)
  - 'utm_campaign' — название кампании
  - 'utm_content' — содержание объявления
  - 'utm_term' — ключевые слова
  - 'gclid' — Google Click ID
  - 'yclid' — Yandex Click ID
  - 'fbclid' — Facebook Click ID
  - 'from' — дополнительный параметр источника (`string`, null: false)
- **value**: Значение параметра (например, 'google', 'cpc', 'summer_sale_2024') (`string`, null: false)
- **created_at**: Дата и время фиксации UTM-метки (`datetime`, default: now(), null: false)
- **date**: Дата события (для партиционирования) (`date`, default: CAST(now(), 'Date'), null: false)
### Индексы и ключи
- **ORDER BY (`shop_id`, `did`)**: Ключ сортировки, оптимизирующий:
  - `shop_id`: изоляцию данных по магазинам
  - `did`: быстрый доступ ко всем UTM-меткам конкретного устройства (для атрибуции при покупке)
- **PARTITION BY (`toYYYYMM(date)`)**: Партиционирование по месяцам для управления TTL
- **TTL (`date + toIntervalYear(1)`)**: Хранение данных в течение 1 года
