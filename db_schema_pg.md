# Таблица: bulk_campaigns
Синонимы: кампании массовых рассылок, email/SMS-кампании, маркетинговые рассылки, авторассылки.
Использование: для анализа и управления маркетинговыми кампаниями (email, SMS и др.), их планирования, отслеживания статуса, сегментации аудитории, A/B-тестирования, настройки UTM-меток и анализа базовой статистики.
Описание: таблица содержит данные о кампаниях массовых рассылок: настройки, статусы, тайминги, сегменты аудитории, шаблоны и статистику.
- **channel**: Канал коммуникации (email, sms, viber и т.д.) (string)
- **shop_id**: ID магазина (integer)
- **name**: Название кампании (string)
- **subject**: Тема письма (для email) или заголовок сообщения (string)
- **state**: Текущий статус кампании: draft (черновик), planned (запланирована), running (запущена), finished (завершена), stopped (остановлена) и т.д. (string)
- **planing_at**: Планируемая дата и время запуска кампании (datetime)
- **started_at**: Фактическая дата и время запуска кампании (datetime)
- **finished_at**: Фактическая дата и время завершения кампании (datetime)
- **segment_ids**: Массив ID сегментов аудитории, включенных в рассылку (array of integer)
- **exclude_segment_ids**: Массив ID сегментов аудитории, исключенных из рассылки (array of integer)
- **utm_source**: UTM-метка: источник трафика (string)
- **utm_medium**: UTM-метка: тип трафика (string)
- **utm_campaign**: UTM-метка: название кампании (string)
- **archive**: Флаг, находится ли кампания в архиве (boolean)
- **total_count**: Общее количество запланированных отправлений в кампании (integer)
- **boost**: Флаг использования функции "Буст" (досылка непрочитанных сообщений) (boolean)
- **boost_count**: Количество отправлений, сделанных в рамках "Буста" (integer)
- **hour_limit**: Часовой лимит на отправку сообщений для данной кампании (integer)
- **warming_up**: Флаг участия кампании в "прогреве" отправителя (повышение репутации email-отправителя) (boolean)
- **template**: Шаблон сообщения (текст/HTML) (text)
- **template_data**: Данные (переменные) для подстановки в шаблон в формате JSON (jsonb)
- **settings**: Дополнительные настройки кампании в формате JSON (jsonb)
- **created_at**: Дата и время создания записи о кампании (datetime)
- **updated_at**: Дата и время последнего обновления записи о кампании (datetime)
- **theme_id**: ID связанной темы/дизайна (bigint)
- **theme_type**: Тип связанной темы/дизайна (string)
- **statistic**: Статистика по кампании (отправки, открытия, клики) в формате JSON (jsonb)
- **ab_test**: Флаг, является ли кампания частью A/B-теста (boolean)
- **parent_id**: ID родительской (основной) кампании для A/B-теста (integer)
- **ab_group**: Вес/процент рассылки для данной группы в A/B-тесте (по умолчанию 100) (integer)
- **ab_paused_at**: Дата и время приостановки A/B-теста (datetime)
- **ab_continue_rule**: Правило определения победителя для продолжения рассылки после A/B-теста (например, 'open_rate', 'click_rate') (string)
- **ab_continue_delay**: Задержка (в часах) перед принятием решения о победителе A/B-теста (integer)
- **ab_continue_id**: ID кампании-победителя, которая будет продолжена после A/B-теста (integer)
- **failed_message**: Сообщение об ошибке, если кампания завершилась неудачно (string)
- **utm_term**: UTM-метка: ключевое слово (string)
- **utm_content**: UTM-метка: содержание/различия (string)
- **offline_orders**: Количество офлайн-заказов, атрибутированных на эту кампанию (integer)
- **offline_revenue**: Выручка от офлайн-заказов, атрибутированных на эту кампанию (decimal)
- **not_banning**: Флаг, запрещающий автоматическую блокировку кампании (boolean)
- **launch_repeat**: Настройка повторного запуска кампании (integer)
- **template_vars**: Переменные шаблона по умолчанию (jsonb)
- **subject_for_boost**: Тема письма для сообщений, отправляемых в рамках "Буста" (string)
- **preheader_for_boost**: Прехедер (текст после темы) для сообщений, отправляемых в рамках "Буста" (string)
- **stopped_at**: Дата и время ручной остановки кампании (datetime)
- **editor**: Редактор, использованный для создания шаблона (например, визуальный или код) (string)
- **use_url_shortener**: Флаг использования сокращателя ссылок в кампании (boolean)
- **launch_v2**: Флаг использования новой/обновленной версии механизма запуска кампаний (boolean)
### Индексы и ключи:
- **PRIMARY KEY**: отсутствует (композитный уникальный индекс выступает в роли бизнес-ключа)
- **UNIQUE (shop_id, bulk_campaign_id, client_id)**: гарантирует уникальность получателя в рамках одной кампании
- **INDEX (bulk_campaign_id)**: для быстрого поиска всех получателей кампании
- **INDEX (client_id)**: для истории рассылок по клиенту
- **COMPOSITE (shop_id, bulk_campaign_id, status)**: для выборки получателей по статусу в конкретной кампании
- **COMPOSITE (shop_id, bulk_campaign_id, best_hour)**: для планирования отправок по оптимальному времени
- **COMPOSITE (shop_id, bulk_campaign_id, status, worker_id, next_try_at)**: для распределения задач между воркерами
- **INDEX (shop_id)**: для мультиарендной фильтрации

# Таблица: call_channels

Использование: для справочной информации о каналах поступления звонков (например, телефонная линия, мессенджер, форма обратного звонка)
Описание: справочник каналов, по которым поступают звонки в магазин.
- **shop_id**: ID магазина (integer)
- **name**: Название канала звонков (например, "Горячая линия", "WhatsApp", "Форма на сайте") (string)
- **key**: Уникальный символьный код/идентификатор канала внутри магазина (string)

Описание: справочник событий, которые могут быть зафиксированы в процессе обработки звонка.
- **shop_id**: ID магазина (integer)
- **call_channel**: Ключ канала звонка (из таблицы call_channels), для которого доступно данное событие (string)
- **name**: Название события (string)
- **key**: Уникальный символьный код/идентификатор события внутри канала и магазина (string)

# Таблица: call_themes

Использование: для иерархической классификации тем обращений (например, "Возврат", "Доставка", "Неисправность товара")
Описание: справочник тем звонков с поддержкой древовидной структуры (parent_id). Позволяет группировать обращения по категориям и подкатегориям.
- **shop_id**: ID магазина (integer)
- **call_type**: Ключ типа звонка (из таблицы call_types), к которому относится тема (string)
- **name**: Название темы обращения (string)
- **key**: Уникальный символьный код/идентификатор темы внутри типа и магазина (string)
- **parent_id**: ID родительской темы (для создания иерархии категорий) (integer)

Описание: справочник типов звонков, определяющих общую направленность коммуникации.
- **shop_id**: ID магазина (integer)
- **name**: Название типа звонка (string)
- **key**: Уникальный символьный код/идентификатор типа внутри магазина (string)

# Таблица: campaign_recipients
Синонимы: получатели рассылки, адресаты кампании, очередь отправки, таргетинг кампании
Использование: для анализа аудитории, попавшей в массовую рассылку, отслеживания статусов доставки каждому клиенту, оптимизации времени отправки, управления повторными попытками и распределения нагрузки между воркерами
Описание: таблица содержит информацию о получателях конкретной массовой рассылки (bulk_campaign), статусе отправки, временных зонах и попытках доставки. Используется для планирования времени отправки с учетом наилучшего часа клиента и распределения задач между воркерами.
- **bulk_campaign_id**: ID массовой рассылки (bigint)
- **shop_id**: ID магазина (bigint)
- **client_id**: ID клиента-получателя рассылки (bigint)
- **status**: Статус отправки сообщения. Возможные значения: pending (ожидает отправки), processing (в обработке), sent (отправлено), failed (ошибка доставки), bounced (отказ в доставке), cancelled (отменено) и т.д. (string)
- **attempts**: Количество попыток отправки сообщения данному клиенту. По умолчанию 1 (integer)
- **best_hour**: Рекомендуемый час для отправки сообщения данному клиенту (0-23). Рассчитывается на основе истории взаимодействий для повышения вероятности открытия/прочтения (integer)
- **worker_id**: Идентификатор воркера (сервиса/процесса), который обрабатывает данную отправку (string)
- **tz**: Часовой пояс клиента (например, "Europe/Moscow", "America/New_York") (string)
- **promo_code**: Промокод, закрепленный за данным получателем для данной кампании (string)
- **next_try_at**: Дата и время следующей попытки отправки при неудачной доставке (datetime)
- **lease_until**: Дата и время, до которого отправка "заблокирована" текущим воркером (используется для распределения задач и избежания дублей) (datetime)
- **created_at**: Дата и время создания записи (постановки клиента в очередь рассылки) (datetime)
- **updated_at**: Дата и время последнего обновления записи (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: отсутствует (таблица создана без первичного ключа, id: false)
- **INDEX (bulk_campaign_id)**: для быстрого поиска и фильтрации получателей по конкретной массовой рассылке; оптимизирует запросы типа "показать всех получателей кампании X"
- **INDEX (client_id)**: для ускорения запросов по истории участия клиента в рассылках; оптимизирует сценарии "все кампании, в которые попадал клиент Y"
- **INDEX (shop_id)**: для мультиарендной фильтрации по магазину; базовый индекс для изоляции данных разных магазинов
- **UNIQUE (shop_id, bulk_campaign_id, client_id)**: композитный уникальный индекс, выполняющий роль первичного ключа. Гарантирует, что один и тот же клиент не может быть дважды добавлен в одну кампанию. Это критическое бизнес-правило, предотвращающее дублирование отправок
- **INDEX (shop_id, bulk_campaign_id, best_hour)**: композитный индекс для оптимизации планирования отправок. Используется для выборки получателей с приоритетом по наилучшему времени доставки; ключевой индекс для функционала "умного времени отправки"
- **INDEX (shop_id, bulk_campaign_id, client_id, worker_id)**: композитный индекс для отслеживания, какой воркер обрабатывает конкретного получателя; используется для распределения нагрузки и избежания дублей обработки
- **INDEX (shop_id, bulk_campaign_id, status, worker_id, next_try_at)**: композитный индекс для управления очередью отправок. Позволяет эффективно находить задачи, которые нужно обработать: с определенным статусом, закрепленные за конкретным воркером или ожидающие следующей попытки отправки. Критически важен для масштабируемой обработки очередей
- **INDEX (shop_id, bulk_campaign_id, status)**: композитный индекс для быстрой фильтрации получателей по статусу доставки в рамках конкретной кампании. Оптимизирует запросы типа "сколько получателей в статусе 'sent' в кампании Z"

# Таблица: categories
Синонимы: категории товаров, товарные группы, разделы каталога, номенклатура
Использование: для анализа товарного ассортимента, группировки товаров, расчета маржинальности по категориям, планирования повышения цен/объемов продаж
Описание: справочник категорий товаров. Содержит информацию о названии, коде и плановых показателях увеличения продаж в натуральном и денежном выражении.
- **id**: Уникальный идентификатор категории (serial)
- **name**: Название категории товаров (string, max 255)
- **deletable**: Флаг, разрешающий удаление категории. По умолчанию `true`. Некоторые системные категории могут быть защищены от удаления (boolean)
- **code**: Уникальный символьный код/идентификатор категории. Используется для интеграции с внешними системами, API, импорта/экспорта (string, max 255)
- **increase_units**: Плановый коэффициент увеличения продаж в натуральном выражении (количество единиц товара). Может использоваться для KPI и прогнозирования (decimal)
- **increase_rubles**: Плановый коэффициент увеличения продаж в денежном выражении (выручка в рублях). Может использоваться для KPI и прогнозирования (decimal)
- **taxonomy**: Таксономия категории. --- (string)
- **created_at**: Дата и время создания записи о категории (datetime)
- **updated_at**: Дата и время последнего обновления записи о категории (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: первичный ключ по полю `id` (неявный, создается автоматически для `serial` типа)
- **UNIQUE (code)**: уникальный индекс по символьному коду категории. Гарантирует отсутствие дублей кодов в рамках всей таблицы. Критически важен для целостности данных при интеграции с внешними системами и предотвращения конфликтов идентификаторов

# Таблица: chain_channel_sends
Синонимы: отправки по цепочкам, события отправки в цепочках, доставки сообщений, история отправок
Использование: для отслеживания фактов отправки сообщений клиентам в рамках маркетинговых цепочек (автоворонок, сценариев), агрегации статистики отправок по дням, предотвращения повторных отправок в одном канале
Описание: таблица фиксирует факт отправки сообщения конкретному клиенту в определенном канале в рамках маркетинговой цепочки. Агрегирована по дням — одна запись на один день отправок. Используется для контроля лимитов частоты и анализа воронок.
- **client_id**: ID клиента-получателя сообщения (bigint)
- **chain_id**: ID маркетинговой цепочки (автоворонки, сценария), в рамках которой выполнена отправка (bigint)
- **channel**: Канал коммуникации, по которому выполнена отправка (например, `email`, `sms`, `viber`, `push`) (string)
- **date**: Дата отправки сообщения. Агрегированный ключ — одна запись на комбинацию клиент+цепочка+канал+дата. По умолчанию текущая дата (date)
- **created_at**: Дата и время создания записи. По умолчанию текущий момент времени (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: отсутствует (таблица создана без первичного ключа, `id: false`)
- **INDEX (client_id, channel, chain_id)**: композитный индекс для быстрого поиска истории отправок. Оптимизирует запросы проверки: "отправляли ли мы этому клиенту сообщение в этом канале в рамках данной цепочки сегодня?". Критически важен для предотвращения дублирующих отправок и соблюдения частотных ограничений
### Особенности структуры:
- **Денормализованная агрегация**: таблица хранит не каждое отдельное сообщение, а факт наличия хотя бы одной отправки в определенный день. Это компромисс между детализацией и производительностью
- **Бизнес-логика**: уникальность обеспечивается на уровне приложения через комбинацию полей `client_id`, `channel`, `chain_id`, `date`. Отсутствие уникального индекса может указывать на то, что в один день возможны множественные записи (например, при разных типах сообщений)

# Таблица: chain_delay_messages
Синонимы: отложенные сообщения цепочек, запланированные отправки, сообщения в очереди, отсроченные рассылки
Использование: для хранения сообщений, которые должны быть отправлены клиентам с задержкой в рамках маркетинговых цепочек (автоворонок, сценариев). Критическая таблица для управления очередью отложенных отправок.
Описание: таблица содержит сообщения, запланированные к отправке в будущем в рамках маркетинговых цепочек. Сообщение создается в момент срабатывания триггера, но отправляется только при наступлении времени `delayed_to`. Позволяет реализовывать сценарии с задержкой (например, "напомнить через 3 часа", "отправить через день").
- **shop_id**: ID магазина, которому принадлежит отложенное сообщение (integer)
- **client_id**: ID клиента-получателя сообщения (bigint)
- **chain_id**: ID маркетинговой цепочки (автоворонки, сценария), в рамках которой создано сообщение (integer)
- **channel**: Канал коммуникации для отправки (например, `email`, `sms`, `viber`, `push`) (string)
- **rule**: JSON-объект с правилом задержки. Содержит параметры, определяющие, через какое время и при каких условиях должно быть отправлено сообщение (например, `{"type": "hours", "value": 3}`) (jsonb)
- **args**: JSON-объект с дополнительными аргументами для отправки. Может содержать переменные шаблона, UTM-метки и другие параметры (jsonb)
- **shop_email_id**: ID email-адреса отправителя (для email-канала). Связь с настройками почтовых ящиков магазина (integer)
- **delayed_to**: Дата и время запланированной отправки. Сообщение будет обработано, когда текущее время достигнет этого значения (datetime)
- **body**: Полное содержимое сообщения (HTML для email, текст для SMS и т.д.) (text)
- **text**: Текстовая версия сообщения (для email-рассылок — альтернативная plain-text версия) (text)
- **subject**: Тема сообщения (для email и некоторых других каналов) (text)
- **created_at**: Дата и время создания записи (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: первичный ключ по полю `id` (неявный, создается автоматически)
- **INDEX (chain_id, client_id)**: композитный индекс для поиска всех отложенных сообщений конкретного клиента в рамках конкретной цепочки. Оптимизирует сценарии отмены или обновления запланированных сообщений при изменении поведения клиента
- **INDEX (client_id)**: индекс для быстрого поиска всех отложенных сообщений клиента. Используется при отмене всех запланированных отправок (например, если клиент отписался)
- **INDEX (shop_id, delayed_to)**: композитный индекс для обработки очереди отложенных отправок. Позволяет эффективно выбирать сообщения, время отправки которых наступило, с фильтрацией по магазину. Критически важен для производительности системы рассылок
### Бизнес-логика и особенности:
- **Очередь отложенных задач**: таблица работает как персистентная очередь. Фоновые процессы регулярно сканируют записи, у которых `delayed_to` <= текущего времени, и инициируют отправку
- **Денормализация контента**: сообщения хранятся уже сформированными (`body`, `subject`) на момент создания, даже если отправка произойдет через неделю. Это защищает от изменений в шаблонах после планирования отправки
- **Управление нагрузкой**: индекс по `(shop_id, delayed_to)` позволяет обрабатывать очереди независимо для разных магазинов и распределять нагрузку по времени

- **token**: API-токен для доступа к InSales (string)
- **api_login**: Логин API (string)
- **api_pass**: Пароль API (string)
- **order_sync_webhook**: Настройка вебхука для синхронизации заказов (integer)
- **insales_reviews_enabled**: Флаг включения синхронизации отзывов. По умолчанию `false` (boolean)
- **insales_variants_enabled**: Флаг поддержки вариантов товаров. По умолчанию `false` (boolean)
- **js_tag_id**: ID JS-тега для установки виджета (string)
- **worker_file_id**: --- (string)
- **installed**: Флаг успешной установки интеграции. По умолчанию `false` (boolean)
- **created_at**: Дата и время создания интеграции (datetime)
- **updated_at**: Дата и время последнего обновления (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: первичный ключ по полю `id` (неявный, создается автоматически для `serial` типа)
- **INDEX (shop_id)**: индекс для поиска интеграции по ID магазина

# Таблица: invalid_emails
Синонимы: невалидные email, hard bounces, черный список email
Использование: для хранения email-адресов, которые признаны невалидными/несуществующими (hard bounces). Используется для фильтрации аудитории и поддержания чистоты базы.
Описание: таблица содержит email-адреса, на которые невозможно доставить сообщения (постоянные ошибки). Позволяет исключать их из будущих рассылок.
- **id**: Уникальный идентификатор записи (serial)
- **email**: Невалидный email-адрес (string)
- **reason**: Причина невалидности (например, `mailbox_not_found`, `domain_not_exist`) (string)
- **shop_id**: ID магазина (integer)
- **created_at**: Дата и время добавления в черный список (datetime)
- **updated_at**: Дата и время последнего обновления (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: первичный ключ по полю `id` (неявный, создается автоматически для `serial` типа)
- **UNIQUE (email)**: уникальный индекс по email (гарантирует уникальность в глобальном черном списке)

# Таблица: invoices
Синонимы: счета, инвойсы, платежные документы
Использование: для выставления счетов на оплату услуг платформы, отслеживания статусов оплаты и хранения истории платежей.
Описание: таблица содержит финансовые документы на пополнение баланса или оплату услуг. Интегрирована с платежными системами.
- **shop_id**: ID магазина (bigint)
- **customer_id**: ID пользователя (владельца магазина) (bigint)

- **aasm_state**: Статус счета в конечном автомате (`pending`, `paid`, `cancelled`, `expired`) (string)
- **payment_method**: Способ оплаты (`bank_card`, `yandex_money`, `invoice`, `company`) (string)
- **comment**: Комментарий к счету (string)
- **purpose**: Назначение платежа (string)
- **external_transaction_id**: ID транзакции в платежной системе (string)
- **processed_at**: Дата и время оплаты (datetime)
- **created_at**: Дата и время создания счета (datetime)
- **updated_at**: Дата и время последнего обновления (datetime)
### Индексы и ключи:
- **PRIMARY KEY**: первичный ключ по полю `id` (неявный, создается автоматически)
- **INDEX (currency_id)**: индекс для связи с валютой
- **INDEX (customer_id)**: индекс для поиска счетов пользователя
- **INDEX (shop_id)**: индекс для поиска счетов магазина

- **parent_id**: ID родительской категории в системе (bigint)
- **parent_external_id**: Внешний ID родительской категории из системы-источника (string)
- **root_id**: --- (string)
- **child_id**: --- (string array)
- **name**: Название категории (string)

- **INDEX (external_id)**: индекс для поиска по внешнему ID
- **INDEX (shop_id, is_available)**: частичный индекс с условием `(is_available = true)` для доступных категорий
- **INDEX (shop_id, is_available, url)**: частичный индекс с условием `((is_available = true) AND (url IS NOT NULL))` для SEO-фильтрации
- **INDEX (shop_id)**: частичный индекс с условием `(taxonomy IS NOT NULL)` для категорий с таксономией
- **INDEX (shop_id)**: частичный индекс с условием `((taxonomy IS NULL) AND (name IS NOT NULL))` для категорий без таксономии
- **INDEX (shop_id, lower((name)::text))**: функциональный индекс для поиска по названию без учета регистра

# Таблица: shop_logs
Синонимы: логи магазинов, журнал событий магазина, аудит действий в магазине, история активности, трекинг событий, лог-файл магазина, event log
Использование: Таблица предназначена для записи и хранения событий, происходящих в рамках конкретного магазина. Для аналитика это основной источник данных для построения воронок событий, анализа поведения покупателей и продавцов, расследования инцидентов, отслеживания популярности товаров и аудита действий пользователей (например, кто и когда совершил действие). Позволяет ответить на вопросы: "Какие события чаще всего происходят в магазине?", "Какой товар просматривают/добавляют в корзину?", "Какие действия совершил конкретный покупатель или сотрудник?".
Описание: Таблица представляет собой неструктурированный или слабоструктурированный журнал аудита (лог) всех значимых действий, связанных с работой магазина. Это хронологическая запись событий, где каждое событие характеризуется временем (created_at), субъектом (who или customer_id), объектом (product) и типом действия (event). Такая структура позволяет регистрировать практически любые события без изменения схемы базы данных, что делает её гибким инструментом для сбора аналитики и отладки. Отсутствие строгих ограничений на значения полей who, product и event позволяет использовать их для хранения различных идентификаторов и названий в зависимости от контекста события.
- **shop_id**: Идентификатор магазина, в котором произошло событие. Является внешним ключом к таблице магазинов (скорее всего, shops). Позволяет фильтровать события по конкретной торговой точке. (integer, null: false)
- **customer_id**: Идентификатор покупателя (клиента), инициировавшего событие или в отношении которого оно было совершено. Является внешним ключом к таблице покупателей (скорее всего, customers). Может быть null, если событие связано только с действиями сотрудника магазина или системными процессами. (integer)
- **who**: Субъект действия. В зависимости от контекста, это может быть идентификатор сотрудника, email, имя пользователя или роль ("system", "anonymous"). Поле позволяет понять, кто именно (не обязательно покупатель) совершил действие, если customer_id не применим. (string)
- **product**: Объект действия. Обычно содержит идентификатор или название товара, с которым связано событие (например, "product_id: 123", "Товар 'Молоко'"). Может быть пустым, если событие не относится к конкретному товару. (string)
- **event**: Название или тип произошедшего события. Заранее не определенный список. Примеры: "product_viewed" (просмотр товара), "added_to_cart" (добавление в корзину), "order_created" (создание заказа), "login_attempt" (попытка входа), "price_changed" (изменение цены), "stock_updated" (обновление остатка). (string)
- **created_at**: Дата и время фиксации события. По этому полю строится хронология событий. (datetime, null: false)
- **updated_at**: Дата и время последнего обновления записи лога. В контексте неизменяемых логов это поле обычно равно created_at, но технически может быть обновлено, если запись была изменена задним числом (что не рекомендуется для аудита). (datetime, null: false)
### Индексы и ключи:
- **PRIMARY KEY (id)**: Уникальный идентификатор каждой записи в логе. Обеспечивает уникальность и эффективный доступ к конкретной записи.
- **INDEX (shop_id)**: Индекс по идентификатору магазина. Критически важен для ускорения запросов, фильтрующих события по конкретному магазину. Без этого индекса выборка всех логов одного магазина из миллионов записей была бы крайне неэффективной. Используется для аналитики в разрезе магазинов, построения отчетов и аудита конкретной торговой точки.
